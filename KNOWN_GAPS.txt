KNOWN GAPS - read this before spot-checking

These are deliberate, not bugs I missed:

1. One key, fragments_layout.middot.choisissez.votre.langue, is
   deliberately excluded from auto-translation. Its English value is
   "اختر لغتك &middot; Choisissez votre langue" - it already intentionally
   mixes Arabic and French, shown in the language-picker popup itself to
   preview both scripts to someone who currently only reads the English UI.
   It's copied through unchanged into every language's file instead.

2. Messages that only librarians/admins ever see are still in English:
   the success/error banners on the Manage Users and Manage Genres pages,
   the bulk-import results, and the book-form validation messages (see
   AdminController, GenreService, BookImportController, BookValidator).
   Everything a normal reader can see (sign-up, login, password, reviews,
   reading, sharing, error pages, pop-up confirmations) is translated.
   To translate one of these later: put the text in the three messages*
   files under a new key, and have the Java code put that KEY on the
   model instead of the sentence (the templates already look keys up and
   fall back to showing plain text if it isn't a key).

3. The machine-translated text in messages_ar.properties and
   messages_fr.properties was spot-corrected for the most visible screens
   (home, About, login, privacy, terms, settings, reader). A native
   speaker should still read through the rest before a public launch.
